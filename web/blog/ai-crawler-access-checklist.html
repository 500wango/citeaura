AI Crawler Access Checklist: GPTBot, ClaudeBot, PerplexityBot

Blocking AI scrapers used to be a blanket security recommendation. Today, blocking AI search bots prevents ChatGPT Search, Claude, and Perplexity from indexing your product documentation, pricing, and changelogs. Here is how to configure robots.txt, WAF rules, and server headers to manage AI access with precision.

Updated 1 September 2026 · 10 min read · Server Configuration

By David Park

The 2026 AI Web Crawler Taxonomy

AI providers maintain separate user-agents for broad training data harvesting versus real-time search retrieval:

User-Agent Token Operator Primary Purpose Impact if Blocked
OAI-SearchBot OpenAI SearchGPT & ChatGPT Search retrieval Site will not appear in ChatGPT live search results
GPTBot OpenAI General model training & indexing Site excluded from future base model training sets
PerplexityBot Perplexity Web search indexing & answer grounding Excluded from Perplexity source citation arrays
ClaudeBot Anthropic Claude web retrieval & training data Claude cannot fetch live pages or documentation
Google-Extended Google Gemini & Vertex AI model training Does NOT affect classic Google Search (Googlebot)

Production-Ready robots.txt Configuration

Below is a balanced configuration that protects private application paths while ensuring public marketing pages, documentation, and pricing remain accessible to AI search engines:

# Allow AI Search Crawlers on Public Routes
User-agent: OAI-SearchBot
User-agent: GPTBot
User-agent: PerplexityBot
User-agent: ClaudeBot
Allow: /
Allow: /docs
Allow: /pricing
Allow: /blog
Allow: /llms.txt
Disallow: /app/
Disallow: /admin/
Disallow: /api/
Disallow: /checkout/

# Optional: Opt out of Gemini training without affecting Google Search
User-agent: Google-Extended
Disallow: /

Sitemap: https://example.com/sitemap.xml

Debugging Cloudflare and WAF Blocks

Even with an open robots.txt, your CDN or Web Application Firewall may silently reject AI crawlers with HTTP 403 Forbidden or Cloudflare Managed Challenges.

1. Simulating Crawler User-Agents via cURL

Run these terminal commands against your production domain to verify response headers:

# Test OAI-SearchBot
curl -I -A "Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko; compatible; OAI-SearchBot/1.0; +https://openai.com/bot)" https://yourdomain.com/

# Test PerplexityBot
curl -I -A "Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko; compatible; PerplexityBot/1.0; +https://perplexity.ai/perplexitybot)" https://yourdomain.com/

# Expected response:
# HTTP/2 200
# content-type: text/html; charset=utf-8

2. Cloudflare Security Rules Adjustment

If the response returns HTTP 403 or includes cf-mitigated: challenge:

  • Navigate to Cloudflare Dashboard → Security → WAF → Custom Rules.
  • Create an Allow rule for verified bots: (cf.client.bot) or (http.user_agent contains "OAI-SearchBot") or (http.user_agent contains "PerplexityBot").
  • Ensure Bot Fight Mode is configured to permit verified search engine user-agents.
