AI Crawler Access Checklist: GPTBot, ClaudeBot, PerplexityBot

If AI crawlers cannot fetch your public website, your brand cannot be cited in real-time generative answers. This engineering checklist outlines the exact User-Agent strings, robots.txt syntax rules, WAF configurations, and automated verification tests required for full AI search crawl accessibility.

Updated 1 September 2026 · 10 min read · Technical Checklist

By Elena Torres

Essential 3-point crawler rule:

  • Separate training from search: If you want to appear in citations without granting training rights, allow real-time agents (ChatGPT-User, PerplexityBot) while disallowing training bots (GPTBot, ClaudeBot).
  • Whitelist bots in WAFs: Disable aggressive JS challenges and rate limits on Cloudflare for verified AI search crawlers.
  • Protect private routes: Keep /app, /api, /admin, and authenticated endpoints disallowed.

3. Configuring Cloudflare & WAF rules

Even if your robots.txt permits AI crawlers, your Web Application Firewall (WAF) may silently drop their requests. In Cloudflare, verify the following settings:

  • Bot Fight Mode: Standard "Super Bot Fight Mode" often flags PerplexityBot and ClaudeBot as automated threats. Add a custom WAF Skip Rule for verified AI bot user agents on public paths.
  • Managed Challenges: Ensure public pages (/, /blog/*, /docs/*, /pricing) do not require JavaScript challenges, as text crawlers do not execute interactive CAPTCHAs.
  • Rate Limiting: Configure crawler rate limits to allow bursts up to 30 requests per minute during deep index sweeps.

4. Terminal cURL testing and status validation

Test each crawler's HTTP response directly against your production server using these terminal commands:

# 1. Test GPTBot
curl -i -s -A "Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko; compatible; GPTBot/1.2; +https://openai.com/gptbot)" \
  https://example.com/ | grep -E "HTTP/|Server|content-type"

# 2. Test ClaudeBot
curl -i -s -A "Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko; compatible; ClaudeBot/1.0; +claudebot@anthropic.com)" \
  https://example.com/docs | grep -E "HTTP/|Server|content-type"

# 3. Test PerplexityBot
curl -i -s -A "Mozilla/5.0 (compatible; PerplexityBot/1.0; +https://perplexity.ai/perplexitybot)" \
  https://example.com/pricing | grep -E "HTTP/|Server|content-type"

Ensure the status code is HTTP/2 200 or HTTP/1.1 200 OK. If you receive 403 Forbidden or 503 Service Unavailable, inspect your edge proxy logs.

5. 5 silent crawler block failure modes

  1. Longest match rule precedence: A generic Disallow: /blog-preview/ rule can accidentally block /blog/* if regex anchors ($) are omitted in certain crawler parsers.
  2. CDN edge cache staleness: Updating robots.txt in your git repository does not take effect if your CDN caches the old robots.txt file for 30 days. Always purge the edge cache after editing.
  3. Apex vs www domain divergence: Serving an allow rule on https://example.com/robots.txt while https://www.example.com/robots.txt returns a 404 error breaks crawling for bots querying the www subdomain.
  4. Missing text/plain content type: Ensure /robots.txt returns Content-Type: text/plain; charset=utf-8. Returning text/html causes some bots to ignore the file entirely.
  5. JavaScript redirection loops: Crawlers do not execute JavaScript window redirects. Ensure all canonical redirects are handled at the HTTP 301 server layer.

Frequently asked questions

Does GPTBot respect robots.txt crawl-delay?

OpenAI's GPTBot respects standard robots.txt allow and disallow directives, but does not officially support the non-standard crawl-delay directive. Manage crawl rates through server-side rate limiters if necessary.

Is it possible to track AI crawler visits in Google Analytics?

Standard Google Analytics (GA4) uses client-side JavaScript tags that automated crawlers do not execute. To monitor AI crawler activity, you must analyze server access logs or CDN edge logs (Cloudflare, Caddy, Nginx).

Should staging or development environments allow AI bots?

No. Staging, preview, and development environments should always return User-agent: * Disallow: / and require HTTP Basic Authentication or VPN access to prevent models from indexing unreleased features.
