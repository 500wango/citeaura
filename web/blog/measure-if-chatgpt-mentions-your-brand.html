Measurement — Engineering Guide

How to Measure ChatGPT Brand Mentions

One ChatGPT answer is a single draw from a stochastic generator, not a measurement. A defensible number requires a fixed question cohort, labeled sampling mode, raw JSON traces, and a deterministic match rule. This guide shows the data model, detection code, and variance math we use at CiteAura.

Why one answer is not a measurement

ChatGPT is non-deterministic even at temperature 0: routing, tool calls, and retrieval freshness shift outputs between runs. A single response to "best CRM for startups" tells you what one generation returned. It does not tell you whether your brand is reliably surfaced for that intent.

Generative Engine Optimization (GEO) borrows from experimental design, not vanity monitoring. You define a population of prompts that represent real buyer intent, draw repeated samples under controlled conditions, and compute a rate with known variance. Change the prompts, the model, or the retrieval mode and you have changed the instrument — you cannot compare the two numbers.

The failure I see most often: teams paste one screenshot of a ChatGPT answer into a deck and call it "AI visibility: 100%" or "0%." That number has no denominator, no repeat, and no mode label. It is not reproducible next Tuesday, let alone next quarter.

Cohort definition: the unit of measurement

A cohort is the smallest unit you can compare over time. Every row in the sample table belongs to exactly one cohort. If any field below changes, start a new series — do not append to the old one.

FieldExampleWhy it is frozen
question_set_idqs_b2b_crm_v3 (15 questions)Adding or rewording a prompt changes the denominator

brand_match_ruleregex v2 + domain normalizerChanging the detector rewrites history

Question set design. 10–20 prompts is the practical minimum. Cover three intent types: category ("best X for Y"), comparison ("X vs Y"), and problem ("how to solve Z"). Exclude prompts that name your brand — "tell me about Acme" measures self-recall, not competitive visibility. Each question gets a stable ID so you can diff mention_rate per question across runs.

Repetition. Run the same set at least 3 times per cohort. At CiteAura the default is 3× per model-mode pair, spaced 6–12 hours apart, to absorb transient retrieval variance. One pass of 15 questions yields n=15; three passes yield n=45, which cuts the standard error by ~42% (variance scales as 1/n).

Rule: if you changed one question, the model name, or the sampling mode, you created a new cohort. Report it as qs_crm_v3/api_param/gpt-4o vs qs_crm_v4/api_param/gpt-4o, not as a trend line.

Sampling modes: label every sample

An unlabeled "ChatGPT said this" log is not comparable. The same prompt answered through different surfaces can use different retrieval paths, system prompts, and tool policies. We enforce three mutually exclusive modes; every stored sample carries one.

ModeHow it is producedWhat it measuresCitations?
API · Model knowledge
api_param		Provider API, no web-search tool, no browsingModel's parametric knowledge at cutoffNo
API · Web-grounded
api_grounded		Provider API with web_search / browsing tool enabledKnowledge + live retrievalSometimes — source URLs when retrieval fires

The hard constraint in CiteAura: API responses and product-UI transcripts never share a cohort. The UI batches context (memory, location, conversation history) that the API call does not have. Mixing them inflates variance and hides the method.

Implementation detail: we store the mode as an enum on every sample row and render it as a badge in the UI. Exports include the mode in the CSV so a downstream analyst cannot accidentally average across modes.

Raw answer JSON: the trace you never throw away

Never store only a boolean. Store the raw answer, then derive mentions. The raw trace is the only artifact that survives a change in the match rule or a dispute about what the model actually said.

{
  "sample_id": "smp_9f3a1b2c",
  "cohort_id": "ch_qs_crm_v3_api_param_gpt4o_us_en",
  "question_id": "q_07",
  "question_text": "What are the best CRM tools for early-stage SaaS teams?",
  "market": "US",
  "lang": "en-US",
  "model": "gpt-4o-2024-08-06",
  "sampling_mode": "api_param",
  "created_at": "2026-08-19T08:14:22Z",
  "latency_ms": 1824,
  "raw_answer": "For early-stage SaaS, strong options include HubSpot, Pipedrive, and Attio. HubSpot offers a generous free tier... Pipedrive is lightweight for outbound... Attio is popular with modern teams that want a flexible data model...",
  "tokens": { "prompt": 18, "completion": 212 },
  "tool_calls": [],
  "citations": [],
  "mention": {
    "brand": "Attio",
    "matched": true,
    "rule_id": "brand_match_v2",
    "spans": [{ "start": 89, "end": 94, "surface": "Attio" }]
  }
}

What matters in this schema:

  • raw_answer is verbatim, not summarized. Truncation, if any, is flagged in a separate truncated field — never silently.
  • tool_calls and citations are empty here because api_param called no retrieval. In api_grounded they carry the search queries and returned URLs.
  • mention is a derived field. Re-running detection with a new regex does not require re-sampling; it re-scores the stored traces.
  • Failed samples (timeout, content filter, empty completion) are stored with status: "failed" and excluded from the denominator. They do not count as "not mentioned."

At CiteAura the file lands at work/<tenant>/<slug>/samples/<date>/<sample_id>.json — filesystem as SSOT, Postgres only indexes cohort and job metadata. You can re-score a full cohort with one script without touching the database.

Mention detection: regex, not vibes

A mention is a deterministic string match against a configured brand surface. Retrieval citations are a separate signal. "No link" does not mean "no mention" — many parametric answers name a brand without returning a URL.

We normalize both the brand configuration and the raw answer before matching:

  1. Unicode NFKC, lowercase, collapse whitespace. Strip zero-width characters the model occasionally emits.
  2. Canonicalize the official domain: strip scheme, www., trailing slash, lowercase. https://www.Acme.co/ → acme.co.
  3. Match brand name as a word-bounded regex. Match domain as a host-bounded pattern so acme.co does not fire on acme.company.com unless configured.
  4. Alias list is explicit and versioned. "Attio" does not implicitly match "Attio CRM" unless you add that alias.
import re, unicodedata

def normalize(text: str) -> str:
    text = unicodedata.normalize("NFKC", text).lower()
    text = re.sub(r"[\u200b\u200c\u200d\ufeff]", "", text)
    text = re.sub(r"\s+", " ", text).strip()
    return text

def build_brand_regex(brand: str, aliases: list[str], domain: str) -> re.Pattern:
    # brand + aliases as word-bounded alternation
    names = [brand] + aliases
    name_pat = "|".join(re.escape(normalize(n)) for n in names)
    # domain: match host with optional scheme/path prefix
    dom = re.escape(normalize(domain).removeprefix("www."))
    domain_pat = rf"(?:https?://)?(?:www\.)?{dom}(?:/|\\b)"
    return re.compile(rf"(?:\b(?:{name_pat})\b|{domain_pat})")

pat = build_brand_regex("Attio", ["Attio CRM"], "attio.com")
assert pat.search(normalize("Try Attio for startups."))  # brand name hit
assert pat.search(normalize("See https://www.attio.com/pricing"))  # domain hit
assert not pat.search(normalize("attio-company is different"))  # no false alias

Why regex over embedding similarity? Determinism and auditability. A stakeholder can read the pattern and verify every span. Embedding thresholds drift with the encoder and are not reproducible without pinning the exact model bytes.

Rank is recorded only when the answer actually ranks. Many answers are unordered prose ("strong options include X, Y, Z"). We do not synthesize a rank from mention order. When the answer does contain an explicit ordered list, we extract first_mention_position and rank as separate fields; both are nullable.

Mention rate: the formula

For a cohort with n successful samples:

mention_rate = mentioned / n_successful
# mentioned  = count where brand regex matched (true/false per sample)
# n_successful = total samples minus failed (timeout, empty, filtered)

Concrete example: a 15-question set run 3 times yields 45 samples. If 2 fail (one timeout, one content filter) and 13 of the remaining 43 contain a match:

mention_rate = 13 / 43 = 0.302 ≈ 30.2%

Report the triple — rate, numerator, denominator — every time. "30% mention rate (13/43, 2 failed, cohort qs_crm_v3 / api_param / gpt-4o / US-en)" is a measurement. "30%" alone is not.

import json, pathlib, re

samples = [json.loads(p.read_text()) for p in pathlib.Path("work/acme/crm/samples/2026-08-19").glob("*.json")]
successful = [s for s in samples if s.get("status", "ok") == "ok"]
mentioned = [s for s in successful if s["mention"]["matched"]]
rate = len(mentioned) / len(successful) if successful else None
print(f"{rate:.1%} ({len(mentioned)}/{len(successful)}, {len(samples)-len(successful)} failed)")

Do not fabricate ranks. Do not impute unmeasured providers as 0%. An unmeasured model stays absent from the report; rendering it as 0% is a data-integrity bug.

Variance analysis: when a change is real

A mention rate is a binomial proportion. Its sampling variance is:

Var(p) = p * (1 - p) / n
SE(p)  = sqrt(Var(p))

# 95% Wilson interval (better than Wald for small n and p near 0 or 1)
# z = 1.96 for 95%
# p_wilson = (p + z²/(2n) ± z*sqrt(p*(1-p)/n + z²/(4n²))) / (1 + z²/n)
import math

def wilson(p, n, z=1.96):
    denom = 1 + z**2 / n
    center = p + z**2 / (2*n)
    margin = z * math.sqrt(p*(1-p)/n + z**2/(4*n**2))
    return (center - margin)/denom, (center + margin)/denom

for n in [15, 45, 90]:
    lo, hi = wilson(0.30, n)
    print(f"n={n:2d}  p=30%  95% CI [{lo:.1%}, {hi:.1%}]  SE={math.sqrt(0.3*0.7/n):.1%}")

# n=15  p=30%  95% CI [12.8%, 54.3%]  SE=11.8%
# n=45  p=30%  95% CI [18.6%, 44.6%]  SE=6.8%
# n=90  p=30%  95% CI [21.5%, 40.1%]  SE=4.8%

Reading the table: with n=15 (one pass of 15 questions), a 30% rate is compatible with anything from 13% to 54% at 95% confidence. You cannot call a move from 30% to 45% a win — it is noise. At n=45 the interval tightens to roughly 19–45%; at n=90 it is 22–40%. That is why we default to repeated passes before drawing a conclusion.

Detecting a real shift between two cohorts. Use a two-proportion z-test or compare non-overlapping Wilson intervals as a conservative heuristic. If cohort A is 13/43 (30%) and cohort B after a content push is 26/44 (59%), the intervals barely overlap — that is worth investigating. If B is 18/44 (41%), the intervals overlap substantially; collect another 30–45 samples before deciding.

Per-question variance. Aggregate rate hides structure. Always break out mention_rate by question. A brand can be 100% on "best free CRM" and 0% on "CRM with SOC 2" — the aggregate 50% is not actionable. CiteAura reports both the cohort rollup and the per-question grid so you see where the gap is.

Failure modes and how to handle them

Retrieval not triggered (api_grounded)tool_calls: [] despite grounded modeMark the sample, exclude from grounded analysis or treat as parametric. Do not average grounded and parametric draws.

Alias collision"Aura" matches "Aura CRM" and "Aura migraine"Require word boundaries and an explicit alias list. Review a random 20 matches per cohort for false positives.

Sampling at temperature > 0 without repeatsHigh run-to-run variance, anecdotal screenshotsFix temperature (0 or 0.2) and repeat. CiteAura defaults to 0.2 for realistic variance while keeping draws comparable.

Two anti-patterns to delete from your workflow: (1) averaging across sampling modes to produce a single "AI visibility score" — you just averaged two different instruments; (2) filling unmeasured slots with 0% — an absent measurement is not evidence of absence.

A mention rate is not a ranking promise

Answers vary by model version, region, and retrieval freshness. A higher mention_rate on a fixed cohort is evidence about that sample under those conditions. It does not guarantee that ChatGPT will mention or rank the brand for every user, especially when the user carries memory, custom instructions, or a prior conversation.

What a rate can support: (1) prioritizing which questions to close the gap on, (2) testing whether a content change moved the needle within the same cohort, (3) reporting coverage alongside per-question detail and confidence intervals. What it cannot support: a claim that the brand "ranks #2 on ChatGPT" — ChatGPT rarely returns a stable numeric rank, and when it does, the rank is conditioned on retrieval results at that instant.

If a stable cohort is persistently at 0% — for example 0/43 across three passes — the likely causes are retrieval gaps or missing category association, not a sampling fluke. Continue at Why ChatGPT Does Not Mention Your Brand for the remediation sequence.

Checklist: run this in one afternoon

  1. Lock 15 buyer-intent questions. Hash the text, assign IDs, commit them.
  2. Choose one sampling mode (start with api_param). Fix model version and market.
  3. Run 3 passes. Store raw JSON with mode and timestamps. Do not filter in the probe step.
  4. Apply the versioned regex. Compute mention_rate = mentioned / n_successful and Wilson intervals.
  5. Break out per-question rates. Sort by gap — the 0% questions are the backlog.
  6. Repeat next week with the identical cohort before claiming a trend. If you changed one question, label the cohort v4 and keep it separate.

FAQ: measuring ChatGPT brand mentions

Can one ChatGPT reply measure brand visibility?

No. A single reply is one draw. Use a fixed question set, repeat it, and compare only within the same cohort (same questions, model, market, and sampling mode). Otherwise you are comparing different instruments.

What should a ChatGPT mention log include?

Question ID and text, raw answer verbatim, timestamp, market and language, model version and fingerprint, sampling mode, the exact regex or rule ID that marked the mention, and the character spans of each hit. Store JSON — not a screenshot.

Can API results be compared with the ChatGPT product UI?

Keep them in separate cohorts. A developer API without retrieval and the consumer ChatGPT app with browsing, memory, and a different system prompt are distinct generators. Mixing them hides method and inflates variance.

How many samples are needed to detect a real change?

Variance is p(1-p)/n. At p=30%, n=15 yields a 95% Wilson interval of ~13–54% — too wide to call a 15-point move a win. At n=45 the interval is ~19–45%; at n=90 it is ~22–40%. Default to 3 passes of a 15-question set (45 samples) before reacting, and 90+ samples before reporting a trend externally.
