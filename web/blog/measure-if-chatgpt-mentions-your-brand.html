Measurement — Engineering Guide

How to Measure ChatGPT Brand Mentions

Ask ChatGPT the same question twice and you may get two different brand lists. That is normal model behavior, but it makes screenshots a poor measurement tool. To track mentions properly, you need a fixed set of questions, a named sampling mode, the raw answers, and one repeatable rule for deciding what counts as a mention.

Updated 20 August 2026 · 12 min read · Technical

By Alex Chen

Why one answer is not a measurement

Even with temperature set to 0, routing, tool calls, and retrieval freshness can change the answer. A response to "best CRM for startups" records one generation at one moment. It says very little about how often the brand appears for that intent.

A useful measurement starts with buyer questions and repeats them under controlled conditions. The resulting rate has a denominator and a known amount of variance. Change the questions, model, market, or retrieval mode, and you have changed the experiment; the new result belongs in a separate series.

This is where screenshot-based reporting falls apart. A slide that says "AI visibility: 100%" may describe one answer out of one. Without the question set, sampling mode, and raw response, nobody can reproduce it next week.

Cohort definition: the unit of measurement

A cohort is the unit you compare over time. Every sample belongs to one cohort, defined by the fields below. When one of them changes, the next samples start a new series.

FieldExampleWhy it is frozen
question_set_idqs_b2b_crm_v3 (15 questions)Adding or rewording a prompt changes the denominator

Designing the question set. A practical baseline uses 10–20 prompts across category searches ("best X for Y"), comparisons ("X vs Y"), and problem-led searches ("how to solve Z"). Leave the brand name out. "Tell me about Acme" measures recall after prompting for Acme, not whether the brand surfaces in a competitive answer. Stable question IDs let you compare each intent across runs.

Repeating the set. Run at least three passes per cohort. CiteAura's sampling API supports repeated calls for each model-mode pair; if you want a 6–12 hour gap between passes, schedule separate jobs rather than treating one immediate batch as a time-separated baseline. Fifteen questions produce n=15 in one pass and n=45 across three; because variance scales as 1/n, the larger sample cuts standard error by about 42%.

A changed question, model, or sampling mode means a changed cohort. Label the two series explicitly, for example qs_crm_v3/api_param/gpt-4o and qs_crm_v4/api_param/gpt-4o, instead of joining them into one trend line.

Sampling modes: label every sample

"ChatGPT said this" is missing an important detail: where and how the answer was produced. The API and the consumer product can use different system prompts, retrieval paths, and tool policies. CiteAura keeps three modes separate and writes the mode onto every sample.

API responses and product-UI transcripts therefore never share a cohort. The product may carry memory, location, conversation history, or other context that the API call does not have. Combining the two would make any movement in the rate difficult to explain.

The mode is stored with each sample, shown in the interface, and included in CSV exports. That label stays attached when the data leaves the workspace.

Keep the raw answer

A mention boolean is derived data. The raw answer is the evidence behind it. Keeping both means you can change the matching rule later, inspect a disputed result, or correct an alias without running the model again.

{
  "run_id": "sample-20260819T081422Z-9f3a1b2c",
  "cohort_id": "ch_qs_crm_v3_api_param_gpt4o_us_en",
  "question_id": "q_07",
  "question": "What are the best CRM tools for early-stage SaaS teams?",
  "market": "US",
  "lang": "en-US",
  "raw_model": "gpt-4o-2024-08-06",
  "sampling_mode": "api_param",
  "ts": "2026-08-19T08:14:22Z",
  "platform": "openai",
  "platform_name": "OpenAI",
  "answer": "For early-stage SaaS, strong options include HubSpot, Pipedrive, and Attio. HubSpot offers a generous free tier... Pipedrive is lightweight for outbound... Attio is popular with modern teams that want a flexible data model...",
  "citations": [],
  "analysis": {
    "brand_mentioned": true,
    "brand_rank": 0,
    "own_domain_cited": false,
    "competitors_mentioned": []
  }
}

Four details make this record useful later:

  • answer is stored verbatim. If the provider truncates it, the run keeps its stop metadata so the answer can be excluded from rank analysis.
  • citations is empty here because api_param called no retrieval. In api_grounded it carries the returned source URLs.
  • analysis is derived data. Re-running detection with a new alias rule can re-score the stored traces without another model call.
  • Timeouts, content filters, and empty completions use status: "failed". They are tracked, but they are not counted as successful answers without a mention.

CiteAura stores API samples as JSONL under work/<tenant>/<slug>/samples/<run_id>.jsonl. The filesystem remains the source of truth for pipeline artifacts, while Postgres indexes cohort and job metadata. Re-scoring reads those stored answers directly.

Detect mentions with a rule you can inspect

A mention is a deterministic match against the configured brand name, aliases, or official domain. Citations are measured separately: an answer can name a brand without linking to it.

We normalize both the brand configuration and the raw answer before matching:

  1. Unicode NFKC, lowercase, collapse whitespace. Strip zero-width characters the model occasionally emits.
  2. Canonicalize the official domain: strip scheme, www., trailing slash, lowercase. https://www.Acme.co/ → acme.co.
  3. Match brand name as a word-bounded regex. Match domain as a host-bounded pattern so acme.co does not fire on acme.company.com unless configured.
  4. Alias list is explicit and versioned. "Attio" does not implicitly match "Attio CRM" unless you add that alias.
import re, unicodedata

def normalize(text: str) -> str:
    text = unicodedata.normalize("NFKC", text).lower()
    text = re.sub(r"[\u200b\u200c\u200d\ufeff]", "", text)
    text = re.sub(r"\s+", " ", text).strip()
    return text

def build_brand_regex(brand: str, aliases: list[str], domain: str) -> re.Pattern:
    # brand + aliases as word-bounded alternation
    names = [brand] + aliases
    name_pat = "|".join(re.escape(normalize(n)) for n in names)
    # domain: match host with optional scheme/path prefix
    dom = re.escape(normalize(domain).removeprefix("www."))
    domain_pat = rf"(?:https?://)?(?:www\.)?{dom}(?:/|\\b)"
    return re.compile(rf"(?:\b(?:{name_pat})\b|{domain_pat})")

pat = build_brand_regex("Attio", ["Attio CRM"], "attio.com")
assert pat.search(normalize("Try Attio for startups."))  # brand name hit
assert pat.search(normalize("See https://www.attio.com/pricing"))  # domain hit
assert not pat.search(normalize("attio-company is different"))  # no false alias

Regex is deliberately plain here. A reviewer can read the pattern and inspect every matched span. Embedding similarity would add a threshold and encoder version that also need to be pinned before the result is reproducible.

Rank is only recorded when the answer presents an actual ranking. Unordered prose such as "strong options include X, Y, Z" does not create ranks 1, 2, and 3. For ordered answers, first_mention_position and rank remain separate, nullable fields.

Mention rate: the formula

For a cohort with n successful samples:

mention_rate = mentioned / n_successful
# mentioned  = count where brand regex matched (true/false per sample)
# n_successful = total samples minus failed (timeout, empty, filtered)

Suppose a 15-question set runs three times. That produces 45 attempts. One times out, one hits a content filter, and 13 of the 43 successful answers mention the brand:

mention_rate = 13 / 43 = 0.302 ≈ 30.2%

The useful result is the full line: "30.2% mention rate (13/43, 2 failed, cohort qs_crm_v3 / api_param / gpt-4o / US-en)." The percentage alone hides both sample size and failures.

import json, pathlib, re

path = pathlib.Path("work/acme/crm/samples/sample-20260819T081422Z-9f3a1b2c.jsonl")
samples = [json.loads(line) for line in path.read_text().splitlines() if line.strip()]
successful = [s for s in samples if s.get("ok") is True]
mentioned = [s for s in successful if (s.get("analysis") or {}).get("brand_mentioned")]
rate = len(mentioned) / len(successful) if successful else None
print(f"{rate:.1%} ({len(mentioned)}/{len(successful)}, {len(samples)-len(successful)} failed)")

Unmeasured providers remain unmeasured. Showing them as 0% would turn missing data into a negative observation.

How much movement is probably noise?

Mention rate is a binomial proportion, so its uncertainty depends heavily on sample size:

Var(p) = p * (1 - p) / n
SE(p)  = sqrt(Var(p))

# 95% Wilson interval (better than Wald for small n and p near 0 or 1)
# z = 1.96 for 95%
# p_wilson = (p + z²/(2n) ± z*sqrt(p*(1-p)/n + z²/(4n²))) / (1 + z²/n)
import math

def wilson(p, n, z=1.96):
    denom = 1 + z**2 / n
    center = p + z**2 / (2*n)
    margin = z * math.sqrt(p*(1-p)/n + z**2/(4*n**2))
    return (center - margin)/denom, (center + margin)/denom

for n in [15, 45, 90]:
    lo, hi = wilson(0.30, n)
    print(f"n={n:2d}  p=30%  95% CI [{lo:.1%}, {hi:.1%}]  SE={math.sqrt(0.3*0.7/n):.1%}")

# n=15  p=30%  95% CI [12.8%, 54.3%]  SE=11.8%
# n=45  p=30%  95% CI [18.6%, 44.6%]  SE=6.8%
# n=90  p=30%  95% CI [21.5%, 40.1%]  SE=4.8%

With n=15, an observed 30% rate has a 95% Wilson interval of roughly 13–54%. A later result of 45% still sits comfortably inside that range. At n=45 the interval narrows to about 19–45%, and at n=90 to 22–40%. Repeated passes are what turn an interesting screenshot into a result worth comparing.

For two cohorts, use a two-proportion z-test or compare Wilson intervals as a conservative first check. Moving from 13/43 (30%) to 26/44 (59%) after a content change is large enough to investigate. Moving to 18/44 (41%) is less persuasive because the intervals overlap substantially; another 30–45 samples would tell you more.

The aggregate can also hide the useful part of the result. A brand might appear for every "best free CRM" question and never appear for "CRM with SOC 2." Both the cohort rollup and the per-question rates matter because the second view identifies the actual content gap.

Most reporting errors come from collapsing distinctions the data still needs. Averaging API, grounded, and product-surface samples produces a score with no stable interpretation. Filling an unmeasured provider with 0% has the same problem: absence of a measurement is not evidence that the brand was absent.

What the rate can and cannot tell you

A higher mention rate on a fixed cohort is evidence about those samples under those conditions. It does not guarantee that ChatGPT will mention or rank the brand for every user. Model versions, region, retrieval freshness, memory, and conversation history can all change the answer.

The rate is still useful. It can show which questions have the largest gap, whether a content change coincided with movement in the same cohort, and how broad the observed coverage is once sample size and confidence intervals are included. It cannot support a blanket claim such as "the brand ranks #2 on ChatGPT." Most answers do not expose a stable numeric rank, and retrieval can change between runs.

A stable cohort that remains at 0% — for example 0/43 across three passes — deserves a closer look at retrieval and category association. The next diagnostic steps are covered in Why ChatGPT Does Not Mention Your Brand.

A practical first measurement

  1. Lock 15 buyer-intent questions. Hash the text, assign IDs, commit them.
  2. Choose one sampling mode (start with api_param). Fix model version and market.
  3. Run 3 passes. Store raw JSON with mode and timestamps; classify failures after collection.
  4. Apply the versioned regex. Compute mention_rate = mentioned / n_successful and Wilson intervals.
  5. Break out per-question rates. The questions with persistent 0% results are candidates for investigation.
  6. Repeat with the identical cohort before calling the movement a trend. If one question changes, label the next set v4 and keep the series separate.

FAQ: measuring ChatGPT brand mentions

Can one ChatGPT reply measure brand visibility?

No. It records one draw. A measurement repeats a fixed question set and compares results only when the questions, model, market, and sampling mode match.

What should a ChatGPT mention log include?

Keep the question ID and text, raw answer, timestamp, market and language, model version and fingerprint, sampling mode, matching rule ID, and the character spans for each hit. A screenshot may be useful for presentation, but it is not the source record.

Can API results be compared with the ChatGPT product UI?

Keep them in separate cohorts. An API call without retrieval and the ChatGPT product with browsing, memory, and a different system prompt are different sampling environments.

How many samples are needed to detect a real change?

Variance is p(1-p)/n. At p=30%, n=15 gives a 95% Wilson interval of about 13–54%. At n=45 it narrows to about 19–45%, and at n=90 to 22–40%. Three passes of a 15-question set provide a workable baseline; an external trend claim usually needs more evidence.
